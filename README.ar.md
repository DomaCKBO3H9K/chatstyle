# chatstyle

[English](README.md) | [Русский](README.ru.md) | [Español](README.es.md) | [Français](README.fr.md) | [中文](README.zh.md) | **العربية**

أداة سطر أوامر (مع نافذة سطح مكتب) للتحقق من نسبة رسائل المحادثات الروسية إلى كاتبها. تجيب عن السؤال: «هل كتب الشخص نفسه رسائل المرسل المجهول ورسائل المرشَّح؟»، وتُظهر السمات التي تستند إليها الإجابة.

> **النتيجة تقدير إحصائي لتشابه الأسلوب، وليست دليلاً على نسبة النص إلى كاتبه.** قد تكون خاطئة، وتتوقف على كمية النص، ولا ينبغي استخدامها أساساً وحيداً للحكم على الأشخاص. انظر [القيود](#القيود) و[الأخلاقيات والخصوصية](#الأخلاقيات-والخصوصية).

> **الحالة: الإصدار 0.1، قبل الإصدار v1.0.** لم تُنشر بعد نتائج الجودة على بيانات حقيقية، انظر [تقييم الجودة](#تقييم-الجودة) و[الحالة والثغرات المعروفة](#الحالة-والثغرات-المعروفة).

مخرجات سطر الأوامر والتقارير ورسائل الخطأ باللغة الروسية (أما النافذة نفسها فمترجمة إلى ست لغات). تعرض الأمثلة أدناه المخرجات الحقيقية كما هي.

## ما الذي تفعله الأداة

- **مجموعة طرق قائمة على الأسلوب.** يُرتَّب المرشَّحون افتراضياً بحسب: «هيكل» الكلمات الوظيفية، وBurrows Delta، ونموذج لغوي على نص أُخفيت فيه الكلمات النادرة (فلا يكاد الموضوع يؤثر)، بأوزان متساوية لدرجات z. يضيف الخيار `--lexical` المفردات (انظر «كيف تقرأ النتيجة»). أما الاختبار على محادثات حقيقية ففي «الحالة والثغرات المعروفة».
- **ثلاث طرق مقارنة** (تُحسب كلها محلياً):
  - تشابه جيب التمام لـ n-gram الأحرف (1-4) بوزن TF-IDF، وهو الأساس، مع شرح لأي n-gram تطابقت؛
  - **Burrows Delta** على سمات الأسلوب: عادات علامات الترقيم (الأقواس «)» و«))» والحذف و«!!» و«??» والفواصل وحروف العطف والمسافات حول العلامات والشرطات وعلامات الاقتباس)، والحالة والإملاء (الأحرف الكبيرة والكلمات الممدودة وكتابة «тся/ться» وخلط السيريلية باللاتينية والمسافات المزدوجة والكتابات غير المعيارية)، و«ё»/«е»، والأحرف اللاتينية، والرموز التعبيرية، وثراء المفردات، وأطوال الكلمات والجمل والرسائل، وتكرار الكلمات الوظيفية والحشو (نحو 40 سمة في المجموع، وهي نفسها تشكّل ملف الأسلوب)؛
  - **General Impostors**: هل نص المرشَّح أقرب باطّراد إلى النص المجهول من نصوص كُتّاب غرباء. درجته (0..1) هي **الدرجة النهائية**.
- **ثلاثة مصادر بيانات:** ملف نصي، وتصدير JSON من Telegram Desktop، وتيليجرام عبر Telethon.
- **تقارير** بصيغتي Markdown وHTML: جدول، وأبرز السمات المتطابقة، وفروق الأسلوب، ووصف للطريقة.
- **ملف أسلوب** لكاتب واحد: `chatstyle features`.
- تحذير إذا كان لدى أحد الطرفين أقل من 1000 كلمة.

## بداية سريعة

يحتوي المستودع على ملفات صغيرة خيالية `tests/fixtures/*.txt` (رسالة في كل سطر). بعد [التثبيت](#التثبيت):

```bash
chatstyle compare -u file:tests/fixtures/unknown.txt -c file:tests/fixtures/same.txt -c file:tests/fixtures/other.txt
```

│ Кандидат                      │ Слов │ Сообщений │ Сходство │ Delta │ Impostors (итог) │ Смесь │
├───────────────────────────────┼──────┼───────────┼──────────┼───────┼──────────────────┼───────┤
│ file:tests/fixtures/same.txt  │   79 │        19 │    0.643 │     — │                — │ +1.00 │
│ file:tests/fixtures/other.txt │  116 │        14 │    0.257 │     — │                — │ -1.00 │
└───────────────────────────────┴──────┴───────────┴──────────┴───────┴──────────────────┴───────┘
Порядок: по стилевой смеси (каркас служебных слов, Delta, языковая модель без тем).
Лучший по методам: косинус — file:tests/fixtures/same.txt; Смесь — file:tests/fixtures/same.txt (методы согласны).
Burrows Delta недоступна (file:tests/fixtures/same.txt, file:tests/fixtures/other.txt): слишком мало текста для оценки разброса признаков (нужно не меньше 6 кусков по 200 слов на всё сравнение).
General Impostors недоступен (file:tests/fixtures/same.txt, file:tests/fixtures/other.txt): посторонних авторов 1 из 3; добавьте папку с чужими текстами: --impostors DIR.
Подсказка: у неизвестного автора 81 слов (меньше 1000). На коротком тексте стилевая смесь заметно слабее, лексика точнее: добавьте --lexical.
Внимание: мало текста (меньше 1000 слов): неизвестный автор — 81; file:tests/fixtures/same.txt — 79; file:tests/fixtures/other.txt — 116. Оценка может быть ненадёжной.
Результат — статистическая оценка сходства стиля, а не доказательство авторства.

عناوين الأعمدة: «Кандидат» هو المرشَّح، و«Слов» الكلمات، و«Сообщений» الرسائل، و«Сходство» التشابه، و«Impostors (итог)» الدرجة النهائية لـ General Impostors، و«Смесь» مجموعة الطرق.

الشرطة تعني أن الطريقة غير متاحة: النص قليل جداً (هنا من 80 إلى 120 كلمة لكل كاتب)، فلا يخترع البرنامج رقماً بل يشرح ما ينقص. ويوجد مثال كامل بالطرق الثلاث في [تقرير تجريبي](#تقرير-تجريبي).

## المتطلبات

chatstyle نواة بلغة C++17 مع واجهة Python، لذا يلزم صنفان من الأشياء: أدوات **لبناء** النواة مرة واحدة (أثناء `pip install`)، ومكتبات **لتشغيل** البرنامج.

**تثبّتها بنفسك (أدوات النظام):**

| ما هو | الإصدار | لماذا | من أين تحصل عليه |
|---|---|---|---|
| Python | 3.11 أو أحدث (3.12 في CI، وجُرِّب 3.14 محلياً) | البرنامج نفسه | python.org، أو `apt install python3 python3-venv` |
| مترجم C++17 | MSVC (Visual Studio 2022 Build Tools) أو MinGW-w64 أو GCC أو Clang | يبني النواة | Windows: Build Tools مع حِمل العمل «تطوير سطح المكتب بلغة C++»؛ Linux: `apt install build-essential` |
| CMake | 3.20 أو أحدث | يبني النواة | cmake.org أو `apt install cmake` أو `pip install cmake` |
| ترويسات Python | نفس إصدار Python لديك | لازمة لبناء وحدة Python | Linux: `apt install python3-dev`؛ وفي Windows تأتي مع Python |
| Ninja | أي إصدار (اختياري) | مولّد البناء لـ MinGW-w64 فقط | `pip install ninja` أو مدير الحزم لديك |
| git | أي إصدار (اختياري) | فقط لاستنساخ المستودع ولتنزيل Catch2 عند بناء اختبارات C++ | git-scm.com |

**تُثبَّت تلقائياً بواسطة `pip install .`:**

| الحزمة | الاستخدام |
|---|---|
| `scikit-build-core` (>= 0.10)، `pybind11` (>= 3.0) | بناء النواة (وقت البناء فقط؛ تُجلب إلى بيئة بناء معزولة) |
| `typer` (>= 0.12)، `rich` (>= 13) | سطر الأوامر والجداول |
| `telethon` (>= 1.36) | الوصول إلى تيليجرام (لا يُستخدم إلا عند أمرك) |
| `pywebview` (>= 5) | نافذة التطبيق |
| `cryptography` (>= 42) | تشفير AES-256-GCM للخزنة وللمحادثات المرفوعة |

يحتاج أول `pip install` إلى اتصال بالإنترنت لتنزيل هذه الحزم؛ وبعدها يعمل البرنامج دون اتصال (باستثناء تيليجرام).

**إضافات اختيارية** (`pip install ".[الاسم]"`):

| الإضافة | الحزم | الاستخدام |
|---|---|---|
| `morph` | `pymorphy3`، `pymorphy3-dicts-ru` | أقسام الكلام (`--morph`، للروسية فقط) |
| `dev` | `pytest`، `ruff` | الاختبارات وفحص الشيفرة |
| `experiments` | `matplotlib` | الرسوم البيانية في `experiments/` |

**للنافذة فقط** (`chatstyle gui`؛ ولا يحتاج سطر الأوامر إلى ذلك):

- Windows: بيئة Microsoft Edge WebView2 (موجودة أصلاً في Windows 11 وفي Windows 10 المحدَّث).
- Linux: GTK مع WebKit (`apt install python3-gi gir1.2-webkit2-4.1`) أو Qt (`pip install "pywebview[qt]"`).
- لم يُجرَّب macOS.

لا يحتاج `chatstyle.exe` الجاهز لنظام Windows (انظر أدناه) إلى شيء من هذا: فهو يضم Python وكل المكتبات.

## التثبيت

**الملفات الجاهزة** مرفقة بكل إصدار في [صفحة Releases](https://github.com/DomaCKBO3H9K/chatstyle/releases): `chatstyle.exe` و`chatstyle-gui.exe` لنظام Windows (دون حاجة إلى Python؛ وهي غير موقَّعة، لذا قد ينبّه SmartScreen)، و`chatstyle-linux.tar.gz` لنظام Linux (فُكَّ الضغط وشغّل `./install.sh`)، وحزمة المصدر، و`SHA256SUMS.txt` للتحقق من التنزيلات. وللبناء من المصدر تابع القراءة.

تحتاج إلى Python 3.11+ ومترجم C++17: تُبنى النواة أثناء التثبيت (CMake >= 3.20؛ ويُجلب pybind11 وscikit-build-core تلقائياً). كل ما يلزم مذكور في [المتطلبات](#المتطلبات).

```bash
git clone https://github.com/DomaCKBO3H9K/chatstyle.git
cd chatstyle
pip install .
```

للتحقق:

```bash
chatstyle --version
```

إذا لم يكن مجلد `Scripts` الخاص ببايثون في `PATH`، فاستدعِ `python -m chatstyle ...`.

### Windows

- المترجم: **Visual Studio 2022 Build Tools** (حِمل العمل «تطوير سطح المكتب بلغة C++») أو **MinGW-w64**. خيارات بناء MSVC: `/W4 /utf-8 /permissive-`.
- مع MinGW-w64 اختر مولّد Ninja (هكذا اختُبر البناء على جهاز المؤلف):

  ```powershell
  $env:CMAKE_GENERATOR = "Ninja"
  pip install .
  ```

- **ملف `chatstyle.exe` جاهز** (نحو 18 ميغابايت، دون حاجة إلى تثبيت Python) سيُرفق بالإصدارات. وإلى ذلك الحين يمكنك بناءه بنفسك (يلزم Python ومترجم كما سبق):

  ```powershell
  pip install -e .
  powershell -File packaging\build_exe.ps1            # ملف واحد dist\chatstyle.exe
  powershell -File packaging\build_exe.ps1 -OneDir    # مجلد، للتنقيح
  python packaging/check_exe.py                       # فحص ملف exe المبني (Windows)
  dist\chatstyle.exe --version
  ```

  النقر المزدوج على `chatstyle.exe` يعرض المساعدة وينتظر Enter حتى لا تُغلق النافذة فوراً (من `cmd` وPowerShell لا يحدث ذلك؛ ويعطّل `CHATSTYLE_NO_PAUSE=1` الانتظار). يحفظ exe ملفات المستخدم في `%APPDATA%\chatstyle` لا بجانبه. ويُفكّ ضغط ملف exe الواحد في مجلد مؤقت عند كل تشغيل، لذا يبدأ في ثوانٍ قليلة.

### نافذة التطبيق

إلى جانب سطر الأوامر توجد نافذة: تختار ملف الكاتب المجهول والمرشَّحين، وتضغط «Сравнить» (قارن)، فترى مقياس تشابه مع شروح؛ وتعرض علامة التبويب الثانية ملف أسلوب كاتب واحد. لا تستخدم النافذة الشبكة: الصفحة داخل الحزمة والخطوط خطوط النظام.

```powershell
chatstyle gui                          # من الحزمة المثبَّتة
dist\chatstyle-gui.exe                 # ملف exe جاهز، بلا نافذة طرفية
dist\chatstyle-gui.exe --selftest r.txt  # فحص ذاتي دون إظهار النافذة، وتُكتب النتيجة في r.txt
```

تقوم النافذة على pywebview ومحرك Microsoft Edge WebView2 المدمج في Windows. وهو موجود أصلاً في Windows 11 وفي Windows 10 المحدَّث؛ وإن لم يكن موجوداً تظهر عند التشغيل رسالة برابط المثبِّت. لبناء exe: `powershell -File packaging\build_exe.ps1 -Target gui`. يمكنك تسجيل الدخول إلى تيليجرام من النافذة (زر «Telegram» في الترويسة، انظر «تيليجرام عبر Telethon» أدناه)؛ ولا يمكن إلغاء عملية حساب جارية. السمة فاتحة أو داكنة، واللغة الروسية أو English أو العربية أو Español أو 中文 أو Français: افتراضياً كما في النظام، وتتذكر مفاتيح التبديل في الترويسة الاختيار (تُعرض العربية من اليمين إلى اليسار). النافذة كلها مترجمة؛ أما التقارير ومخرجات سطر الأوامر فتبقى بالروسية، وكذلك النص التفصيلي لأخطاء النواة. لم يراجع ناطقون أصليون الترجمات، والتصحيحات مرحَّب بها: القواميس في `python/chatstyle/gui/web/lang/`.

### Linux

تحتاج إلى `g++` (أو `clang++`) وCMake >= 3.20 وترويسات Python:

```bash
sudo apt install build-essential cmake python3-dev   # Debian/Ubuntu
pip install .
```

تحتاج النافذة (`chatstyle gui`) إضافة إلى GTK (`python3-gi gir1.2-webkit2-4.1`) أو Qt (`pip install "pywebview[qt]"`)؛ أما سطر الأوامر فيعمل بدونهما.

### التطوير

```bash
pip install -e ".[dev]"          # pytest, ruff
pytest                           # اختبارات Python
ruff check python tests experiments
cmake -S . -B build -DCHATSTYLE_BUILD_TESTS=ON -DCHATSTYLE_BUILD_PYTHON=OFF
cmake --build build
ctest --test-dir build           # اختبارات النواة (يُنزَّل Catch2 عند إعداد CMake)
```

للرسوم البيانية في `experiments/` أضف: `pip install -e ".[experiments]"`.

## مصادر البيانات

يُكتب المصدر بالشكل `المخطط:القيمة`. تلزم مرشَّح واحد على الأقل للمقارنة؛ ويمكن تكرار `-c`.

| المصدر | مثال | ما يُؤخذ |
|---|---|---|
| `file:` | `file:chat.txt` | ملف نصي UTF-8، رسالة في كل سطر. |
| `tgexport:` | `tgexport:result.json#Anna Petrova` | تصدير JSON لمحادثة واحدة من Telegram Desktop؛ وبعد `#` اسم المرسل أو `from_id` الخاص به (`user111`) أو معرّف رقمي. |
| `tg:` | `tg:@friend` أو `tg:@group#@person` | رسائل عبر Telethon: محادثة خاصة مع مستخدم، أو رسائل شخص واحد في مجموعة. |
| `chat:` | `chat:777#Anna Petrova` | شخص من **محادثة مرفوعة** (انظر أدناه): قبل `#` معرّف المحادثة أو عنوانها، وبعده اسم المشارك أو `from_id` الخاص به. |

تؤخذ فقط الرسائل النصية للمرسل المطلوب: تُتخطّى الرسائل المحوَّلة ورسائل الخدمة والوسائط التي لا تحمل تعليقاً. وتُستبدل الروابط والإشارات بوسوم؛ وتُهمل الرسائل الفارغة والعبارات البديلة مثل `[Фото]`.

### المحادثات المرفوعة

حتى لا تضطر إلى فرز ملفات التصدير في مجلدات يدوياً، ارفع تصدير المحادثة مرة واحدة فيبقى في القائمة. ويمكن بعد ذلك حذف ملف `result.json` الأصلي: إذ لا يُحفظ إلا نصوص رسائل المشاركين وأوقاتها.

- **في النافذة:** علامة التبويب «Чаты» (المحادثات)، ثم زر رفع تصدير المحادثة؛ وفي المقارنة وفي ملف الأسلوب أزرار للاختيار من المحادثات المرفوعة (ويمكن تحديد عدة مشاركين من محادثة دفعة واحدة).
- **في سطر الأوامر:**

  ```
  chatstyle chats add result.json      رفع محادثة (الرفع مرة أخرى يوسّعها دون تكرار)
  chatstyle chats list                 قائمة المحادثات
  chatstyle chats list Friends         مشاركو محادثة واحدة (الاسم والمعرّف وعدد الرسائل)
  chatstyle chats remove Friends       إزالة محادثة من القائمة
  chatstyle compare -u chat:Friends#Ann -c chat:Friends#Bob -c chat:Friends#Vera
  ```

تُحدَّد المحادثة بالمعرّف الوارد في التصدير أو بعنوانها (وإذا تطابق عنوانا محادثتين فلا بد من المعرّف)، ويُحدَّد المشارك باسمه أو معرّفه (`user111`). وهذا التحليل نفسه المستخدم في `tgexport:` لكن الملف يُقرأ مرة واحدة فقط. تقع ملفات المحادثات في مجلد البيانات (`chats/`) وهي **مشفَّرة** (AES-256-GCM): يُحفظ مفتاح عشوائي في خزنة الأسرار المشتركة (وهي نفسها التي تحفظ تسجيل الدخول إلى تيليجرام: كلمة مرور رئيسية أو DPAPI)، لذا يجب فتح الخزنة قبل العمل مع المحادثات. **لا حاجة لذلك إلى مفاتيح API ولا إلى تسجيل الدخول إلى تيليجرام:** ففي علامة التبويب «Чаты» تعرض النافذة بنفسها إعداد الحماية (كلمة مرور رئيسية أو DPAPI أو «طوال فتح النافذة فقط») أو فتحها بكلمة المرور الرئيسية؛ ويسأل سطر الأوامر الأمر نفسه. تُقفل الخزنة المحمية بكلمة مرور رئيسية تلقائياً بعد 15 دقيقة من الخمول في علامة التبويب «Чаты». وفي وضع «طوال فتح النافذة فقط» تبقى المحادثات في الذاكرة فقط وتختفي عند إغلاق النافذة. أما المحادثات التي رفعتها الإصدارات السابقة (ملفات `*.json` غير المشفَّرة) فتُشفَّر عند فتح الخزنة أول مرة، وتُستبدل النسخ غير المشفَّرة بكتابة فوقها. الملف مرتبط بمعرّفه: فلا يُفكّ تشفير ملف استُبدل أو عُدِّل.

### تيليجرام عبر Telethon

لا تُستخدم الشبكة **إلا** هنا وعند أمرك الصريح فقط.

1. احصل على `api_id` و`api_hash` من <https://my.telegram.org> (قسم API development tools).
2. سجّل الدخول مرة واحدة: يسأل الأمر عن طريقة الحماية (كلمة مرور رئيسية أو حساب Windows)، وعند الحاجة عن مفتاحَي `api_id`/`api_hash` (ويمكن إعطاؤهما أيضاً عبر متغيرَي البيئة `TELEGRAM_API_ID` و`TELEGRAM_API_HASH` أو ملف `.env`)، ثم رقم الهاتف والرمز الذي يرسله تيليجرام وكلمة مرور التحقق بخطوتين إن كانت مفعّلة:

   ```bash
   chatstyle login
   ```

3. قارن (إذا كانت الخزنة محمية بكلمة مرور رئيسية فسيطلبها الأمر دون إظهارها أثناء الكتابة):

   ```bash
   chatstyle compare -u tg:@stranger -c tg:@friend1 -c file:friend2.txt --limit 1000
   ```

**من النافذة.** يفتح زر «Telegram» في الترويسة معالجاً: طريقة حماية تسجيل الدخول، والمفاتيح (`api_id`، `api_hash`)، ورقم الهاتف، ورمز تيليجرام، وكلمة مرور التحقق بخطوتين إن كانت مفعّلة. لا يُحفظ الرمز ولا كلمات المرور أبداً، وتُفرَّغ الحقول فور الإرسال. وبعد تسجيل الدخول يظهر في المصادر خيار «Из Telegram» (محادثة، ومرسل عند الحاجة)، ويقع حد الرسائل و«التحميل من جديد» تحت «Дополнительно». ويستخدم تسجيل الدخول من النافذة و`chatstyle login` الخزنة المشفَّرة نفسها. يمسح «Выйти из Telegram» الجلسة من الخزنة وينهيها من جهة تيليجرام؛ ويحذف «Удалить все данные Telegram» الخزنة نفسها أيضاً. تفاصيل الحماية في [الأمان](#الأمان).

`--limit` (الافتراضي 3000) هو الحد الأقصى للرسائل لكل كاتب؛ ويُخزَّن ما حُمِّل مؤقتاً، وتستخدم عملية التشغيل المتكررة الذاكرة المؤقتة، ويعيد `--refresh` التحميل. وبدون تسجيل الدخول يطلب `compare` مع `tg:` أن تشغّل `chatstyle login`.

## الاستخدام

```bash
chatstyle compare -u file:unknown.txt -c file:a.txt -c file:b.txt \
    --impostors outsider_texts/ --seed 1 --report report.html
chatstyle features file:chat.txt --top 10
chatstyle login
```

| خيار `compare` | المعنى |
|---|---|
| `-u, --unknown` | مصدر الكاتب المجهول |
| `-c, --candidate` | مصدر مرشَّح (يمكن تكراره) |
| `--impostors DIR` | مجلد نصوص غريبة لـ General Impostors: **ملف `.txt` واحد لكل كاتب** (UTF-8، رسالة في كل سطر) |
| `--seed N` | بذرة General Impostors (الافتراضي 1): البذرة نفسها تعطي النتيجة نفسها |
| `--report FILE` | حفظ تقرير؛ والصيغة يحددها الامتداد، `.md` أو `.html` |
| `--style-groups G` | مجموعات سمات الأسلوب لـ Burrows Delta: `all` (الافتراضي) أو `none` أو قائمة مفصولة بفواصل من `punctuation` و`orthography` و`words` و`sentences`؛ ولا تؤثر في الدرجة النهائية لـ General Impostors |
| `--morph` | إضافة عمود «Части речи» (أقسام الكلام): تشابه n-gram لأقسام الكلام (1-4)؛ ويحتاج الإضافة الاختيارية `pip install chatstyle[morph]` (pymorphy3)، للروسية فقط، ولا يؤثر في الدرجة النهائية |
| `--charlm` | إضافة عمود «Языковая модель (бит/символ)» (النموذج اللغوي، بت لكل حرف): بكم بت لكل حرف يكون نص الكاتب المجهول أفضل توقعاً بنموذج أحرف هذا المرشَّح منه بنموذج المرشَّحين الآخرين (فوق الصفر يعني أقرب إلى المرشَّح)؛ ويحتاج مرشَّحين غير فارغين على الأقل، ولا يؤثر في الدرجة النهائية |
| `--wordgrams` | إضافة عمود «Слова (косинус)» (الكلمات، جيب التمام): تشابه n-gram الكلمات (1-4 كلمات متتالية، TF-IDF)؛ والكلمات التي لا يملكها إلا كاتب واحد لا تُميَّز؛ ولا يؤثر في الدرجة النهائية |
| `--emoji` | إضافة عمود «Эмодзи (косинус)» (الرموز التعبيرية، جيب التمام): تشابه الرموز التعبيرية التي يستخدمها الكاتب وترتيبها (1-4 متتالية؛ والرموز المركبة بدرجة لون البشرة وأدوات الربط تُحسب رمزاً واحداً)؛ والكاتب الذي لا يستخدم أي رمز لا درجة له؛ ولا يؤثر في الدرجة النهائية |
| `--rhythm` | إضافة عمود «Ритм (по времени)» (الإيقاع بحسب الوقت): تشابه إيقاع الكتابة (سلاسل الرسائل والتوقفات وأوقات اليوم وعطلات نهاية الأسبوع)؛ ويحتاج تواريخ الرسائل (المصدران `tgexport:` و`tg:`؛ أما `file:` فلا تواريخ فيه) و30 رسالة مؤرَّخة على الأقل لكل كاتب؛ ولا يؤثر في الدرجة النهائية |
| `--lexical` | إضافة المفردات إلى مجموعة الطرق (نموذج لغوي عادي للأحرف وn-gram للكلمات بدلاً من النموذج اللغوي على نص بلا كلمات نادرة): أدق قليلاً في المحادثات المختبَرة (98% مقابل 95%) لكنه أكثر حساسية للموضوع؛ وافتراضياً يُحسب الترتيب بالأسلوب وحده |
| `-n, --limit N`، `--refresh` | لـ `tg:`: حد الرسائل وتحديث الذاكرة المؤقتة |

عند إعادة توجيه المخرجات (`chatstyle compare ... > result.txt`) يُكتب النص بترميز UTF-8.

**أقسام الكلام.** هي مضمَّنة افتراضياً في `chatstyle.exe` و`chatstyle-gui.exe` (pymorphy3، نحو +9 ميغابايت؛ وللبناء بدونها: `powershell -File packaging\build_exe.ps1 -NoMorph`). وعند التشغيل من المصدر تلزم الإضافة: `pip install chatstyle[morph]`. يضيف الأمر `chatstyle compare ... --morph` العمود «Части речи (косинус)»، بينما يعرض `chatstyle features ... --morph` وعلامة التبويب «ملف الأسلوب» في النافذة (خانة «Учитывать части речи») نسب الأسماء والأفعال والأدوات والكلمات الخارجة عن القاموس. تكتفي Python بوسم الكلمات برموز من حرف واحد لأقسام الكلام (pymorphy3، محلياً، بلا شبكة)، وتحسب النواة نفسها التكرارات والـ n-gram على الرموز. الوسم بلا سياق ملتبس («мыла» اسم أم فعل؟)، والعامية والأسماء غير معروفة للقاموس، لذا فالسمة مشوَّشة ولا تؤثر في الدرجة النهائية. وفي النافذة تكون خانات أقسام الكلام والنموذج اللغوي وn-gram الكلمات والرموز التعبيرية والإيقاع مفعّلة منذ البداية (أقسام الكلام إذا كانت في البناء)؛ وفي سطر الأوامر تُفعَّل هذه الطرق بالخيارات `--morph` و`--charlm` و`--wordgrams` و`--emoji` و`--rhythm`.

**النموذج اللغوي للأحرف.** تدرّب النواة لكل مرشَّح نموذجاً للأحرف (سياق حتى ثلاثة أحرف، وتمهيد Witten-Bell، مع الاحتفاظ بحالة الأحرف) وتحسب كم بتاً لكل حرف يلزم «لترميز» نص الكاتب المجهول. ثم يُطرح الرقم نفسه لنموذج المرشَّحين الآخرين: القيمة الموجبة تعني أن النص أقرب إلى هذا المرشَّح. وتُسوّى كمية نص التدريب بين المرشَّحين (لا يؤخذ أكثر مما لدى الأقصر)، وإلا فاز المرشَّح الطويل بحجمه فقط. ومع مرشَّح واحد لا توجد درجة. تُفعَّل الطريقة بالخيار `--charlm` أو بالخانة في النافذة ولا تؤثر بعد في الدرجة النهائية: فلم تُقَس فائدتها على بيانات حقيقية.

**n-gram الكلمات.** يحسب الخيار `--wordgrams` (والخانة في النافذة) تشابه جيب التمام نفسه، لكن على متتاليات من 1-4 كلمات بدلاً من الأحرف: فالعبارات الثابتة («ну вообще»، «в принципе») تسهم أكثر من الحروف المفردة. تُحوَّل الكلمات إلى أحرف صغيرة؛ والكلمة المفقودة عند كاتبين على الأقل من المقارنة لا تؤكد شيئاً وتُستبدل بعلامة مشتركة «كلمة نادرة». وكما في أقسام الكلام، تكتفي Python باستبدال الكلمات برموز وتحسب النواة نفسها الـ n-gram. لا تؤثر في الدرجة النهائية؛ ولم تُقَس فائدتها على بيانات حقيقية.

**الرموز التعبيرية بالتفصيل.** سمة «حصة الرموز التعبيرية» في ملف الأسلوب تقول فقط هل هي كثيرة أم قليلة. أما الخيار `--emoji` (والخانة في النافذة) فيقارن *أيّ رموز بالضبط* وبأي ترتيب: لا يبقى من الرسائل إلا الرموز التعبيرية (والمركبة منها تُحسب كاملة)، ويُعطى كل منها رمزاً، وتحسب النواة نفسها جيب التمام على n-gram من 1-4. والكاتب الذي لا رموز لديه لا درجة له. لا يؤثر في الدرجة النهائية.

**إيقاع الكتابة عبر الزمن.** إذا كان المصدر يعرف متى كُتبت الرسائل (تصدير Telegram Desktop وتحميل `tg:`)، تحسب النواة ثماني سمات من أوقات الكاتب: حصة التوقفات حتى دقيقة، وطول سلاسل الرسائل، والتوقف المعتاد (لا تُحسب التوقفات التي تزيد على ست ساعات، أي استراحة الليل)، وحصص الرسائل ليلاً وصباحاً ونهاراً ومساءً، وحصة عطل نهاية الأسبوع. الوقت «وقت الحائط» كما على ساعة الكاتب (المنطقة الزمنية للحاسوب)، لذا ينبغي مقارنة تصديرات شخص ومحاوره من الجهاز نفسه. يعرض ملف الأسلوب (`chatstyle features`، علامة التبويب «ملف الأسلوب») الإيقاع تلقائياً عند وجوده؛ وفي المقارنة يُفعَّل بالخيار `--rhythm`. السلسلة هي رسائل الكاتب بتوقفات حتى دقيقة (ولا تظهر رسائل المحاور في المصدر). ملفات `file:` بلا تواريخ، فلا إيقاع فيها. لا يؤثر في الدرجة النهائية؛ ولم تُقَس فائدته على بيانات حقيقية. وتحفظ الذاكرة المؤقتة لتيليجرام الوقت الآن أيضاً، لذا لا تُقرأ ذاكرة مؤقتة من إصدار سابق وتُحمَّل الرسائل من جديد.

**عادات لا أخطاء.** تقيس سمات علامات الترقيم والإملاء *العادات الثابتة* للكاتب (كم مرة يمدّ الحروف، ويضع فاصلة قبل حرف العطف، ويكتب «щас» أو «тся»)، لا ما إذا كان شيء ما مكتوباً «بصواب»: لا يُستخدم قاموس ولا مدقق نحوي، ويُحسب كل شيء محلياً. والمهم للمقارنة أن تتطابق عادات النصين. أُعدّت قائمة الكتابات غير المعيارية (`python/chatstyle/resources/nonstandard_ru.txt`) يدوياً ولم يراجعها ناطقون أصليون. تعمل السمات في Burrows Delta وفي ملف الأسلوب فقط؛ أما الدرجة النهائية لـ General Impostors فتُحسب كما سبق من n-gram الأحرف. ولم تُقَس فائدتها على بيانات حقيقية: فالبيانات الاصطناعية لا تتحقق إلا من صحة العدّ (انظر «الحالة والثغرات المعروفة»).

### كيف تقرأ النتيجة

| العمود | المعنى |
|---|---|
| Сходство (التشابه) | جيب تمام n-gram بوزن TF-IDF، 0..1، الأكبر أقرب |
| Delta | Burrows Delta، الأصغر أقرب؛ ولا يقارَن إلا بين مرشَّحي تشغيل واحد |
| Impostors (итог) | **الدرجة النهائية**: حصة 100 تكرار عشوائي يكون فيها نص المرشَّح أقرب إلى المجهول من نصوص كل الغرباء. رقم بين 0 و1 لكنه **ليس احتمالاً** |
| Смесь (مجموعة الطرق) | **ترتيب المرشَّحين**: متوسط درجات z لثلاث إشارات على مرشَّحين بحجم واحد: «هيكل» الكلمات الوظيفية، وDelta، ونموذج لغوي للأحرف على نص بلا كلمات نادرة (ومع `--lexical` يحلّ مكان الأخير نموذج لغوي عادي وn-gram للكلمات)؛ الأكبر أقرب؛ والقيمة نسبية إلى مجموعة مرشَّحي هذا التشغيل. ومع مرشَّحين اثنين تكون حصة «أصوات» الطرق: +1 الكل مع، و-1 الكل ضد |

إذا وُجد مرشَّحان على الأقل تُرتَّب الصفوف بحسب مجموعة طرق الأسلوب؛ وإلا فبحسب Impostors (إن كان متاحاً للجميع)، وإلا فبحسب جيب تمام TF-IDF. وحتى لا يفوز مرشَّح كبير بحجم مفرداته وحده، تُحسب مجموعة الطرق على مرشَّحين بحجم واحد: تؤخذ من كل منهم رسائل عشوائية حتى 2500 كلمة (لكن ليس أقل مما لدى أقصر مرشَّح). وتبقى الأعمدة «Сходство» و«Delta» و«Impostors (итог)» محسوبة على النص كله. وفي النافذة يعرض الشريط القرب *النسبي* بين المرشَّحين (softmax لمجموعة الطرق بدرجة حرارة 1.0، ومجموع الحصص 1)؛ وهذا ليس احتمال نسبة النص إلى كاتبه. ويبيّن سطر «Лучший по методам» (الأفضل بحسب الطرق) هل تتفق الطرق. وحين تختلف فهذه معلومة في ذاتها: لا تختر الطريقة التي تعجبك.

عندما تكون الطرق غير متاحة (شرطة):

- **Delta:** يلزم 6 مقاطع على الأقل من 200 كلمة للمقارنة كلها (نحو 600 كلمة لكاتبين).
- **General Impostors:** يلزم 3 كُتّاب غرباء على الأقل (المرشَّحون الآخرون مع مجلد `--impostors`) ومقطعان على الأقل من 200 كلمة للكاتب المجهول وللمرشَّح. وفي تشغيل «مجهول + مرشَّحين» يوجد غريب واحد لكل مرشَّح، لذا لن توجد درجة نهائية دون `--impostors`: وهذا مقصود.

يحتوي التقرير (`.md` و`.html` مستقل بلا موارد خارجية) على: جدول المرشَّحين، وشرحاً للدرجة النهائية، وأبرز 20 n-gram متطابقة (تُخفى الحروف المفردة والمسافة لقلة فائدتها)، وأهم فروق الأسلوب بحسب Delta بأسماء مقروءة، ومعاملات التشغيل (البذرة وعدد الغرباء)، ووصفاً للطريقة والقيود.

## تقييم الجودة

**لا توجد نتائج بعد.** تحتاج الأرقام الصادقة إلى نصوص حقيقية موسومة لعدة كُتّاب، ولا يملك المشروع مثل هذه المدونة. وأي رقم يُحصل عليه من بيانات مختلقة لن يقول شيئاً عن الجودة في محادثات حقيقية، لذا لا يوجد هنا أي رقم عن قصد.

**اختبار على محادثاتك أنت.** إذا رفعت عدة محادثات (علامة التبويب «Чаты» أو `chatstyle chats add`) فيمكنك اختبار ترتيب المرشَّحين عليها دون أي وسم:

```bash
python -m experiments.chats_eval            # مجموعة طرق الأسلوب (الافتراضي)
# يقرأ الخزنة المشفَّرة (ويسأل عن كلمة المرور الرئيسية)؛ و--chats-dir المجلد يعني ملفات محادثات غير مشفَّرة
python -m experiments.chats_eval --lexical  # مجموعة الطرق مع المفردات
```

يُعدّ معرّف المشارك نفسه في محادثات مختلفة شخصاً واحداً؛ وتُبنى نوعان من المهام: «عبر السياقات» (شخص من محادثة مقابل الآخرين، وتؤخذ نصوصهم من محادثات أخرى) و«بحسب الزمن» (آخر الرسائل مقابل الباقي). لا تُطبع إلا أرقام (حصة المراتب الأولى وMRR والحصة عند التخمين العشوائي)، دون أسماء أو نصوص. وهذا لا يغني عن تقييم على مدونة موسومة (انظر التحفظات في «الحالة والثغرات المعروفة»)، لكنه يتيح التحقق من سلوك الخوارزمية على بياناتك أنت.

أدوات التقييم جاهزة (`experiments/`) ومختبَرة على بيانات اصطناعية:

```bash
# مجموعة البيانات: مجلد، ملف .txt واحد لكل كاتب، أسماء مجهولة، والرسائل مرتبة
python -m experiments.evaluate DATASET --words 1000 --impostors 10 --jobs 4 --output results.json
python -m experiments.volume DATASET --slices 250 500 1000 2000 5000 --jobs 4   # الجودة بحسب الحجم، ورسم بياني
python -m experiments.prepare_tgexport result.json DATASET --min-messages 300   # مجموعة بيانات من محادثة جماعية
```

يُحسب لكل طريقة ROC AUC (مع فاصل ثقة، بإعادة المعاينة على الكُتّاب) والدقة بعتبة اختيرت على بيانات مختلفة. وللتنقيح يوجد `python -m experiments.make_synthetic المجلد`؛ وتوسَم هذه البيانات، وتحذّر النصوص البرمجية مرتين من أن الأرقام لا يجوز نشرها.

يمكن اختبار مجموعات سمات الأسلوب الجديدة (علامات الترقيم والإملاء والكلمات والجمل) واحدة تلو الأخرى: يحسب `python -m experiments.ablation DATASET` قيمة AUC لـ Burrows Delta بدون مجموعات ومع كل مجموعة ومع جميعها، ويشغّل `python -m experiments.evaluate DATASET --style-groups words,sentences` التقييم المعتاد بالمجموعات المختارة. وتُنشأ مجموعة بيانات لكتّاب لهم عادات كتابة مدمجة بالأمر `python -m experiments.make_synthetic المجلد --habits`. وما دامت المدونة غير موجودة فإن مثل هذا التشغيل لا يثبت إلا أن المجموعات تغيّر الدرجة فعلاً، لا أنها مفيدة مع البشر.

عتبة تحذير «أقل من 1000 كلمة» مؤقتة حالياً: وستُضبط بحسب نتائج تقييم على بيانات حقيقية.

## القيود

- **التقدير احتمالي.** هو مقياس لتشابه الأسلوب لا دليل. فالدرجة المرتفعة لا تعني الكاتب نفسه، والمنخفضة لا تعني كُتّاباً مختلفين.
- **لكمية النص أثر كبير.** مع حجم صغير (أقل من 1000 كلمة عند أي من الطرفين) قد تكون الدرجة عشوائية؛ ومع حجم صغير جداً لا يتوفر Delta ولا General Impostors.
- **تتوقف الدرجة النهائية على «الغرباء».** إن كانوا قليلين أو مختلفين عن بيئة التواصل الحقيقية، تشوّهت الدرجة.
- **الأسلوب يتوقف على السياق.** يكتب الشخص الواحد بطريقة مختلفة في محادثات مختلفة، ويكتب أشخاص مختلفون من الدائرة والعمر والموضوع نفسها بطريقة متشابهة.
- **اللغات.** تُحدَّد الأحرف وحالتها بجداول Unicode 16 (اللاتينية بعلاماتها والإغريقية والأرمنية والجورجية والعربية والعبرية والكتابات الهندية وغيرها)، لذا تعمل الطرق القائمة على الأحرف (جيب التمام والنموذج اللغوي و«الهيكل») مع أي نظام كتابة؛ وفي الصينية واليابانية (الرموز التصويرية والكانا) تُحسب كل علامة كلمة. **لكن الدقة لم يُتحقق منها إلا في الروسية.** ففي بيانات اصطناعية لتسع لغات (الإنجليزية والفرنسية والألمانية والإسبانية والبولندية والإغريقية والعربية والصينية واليابانية) يُميَّز كُتّاب بمفردات مختلفة؛ وهذا اختبار لأن الطريقة تعمل لا لدقتها. يعتمد Delta على قوائم روسية للكلمات الوظيفية والحشو و«الكتابات غير المعيارية» وعلى سمات مثل «тся/ться» و«ё/е»، لذا لا يبقى في اللغات الأخرى إلا السمات المستقلة عن اللغة (علامات الترقيم والحالة والأطوال)؛ وأقسام الكلام (`--morph`) للروسية فقط. وفي اللغات الأخرى الأفضل تفعيل `--lexical`. وفي التايلاندية واللاوية والخميرية والبورمية (كتابات بلا مسافات وليست رموزاً تصويرية) تبقى الكلمة سلسلة من الأحرف. ويتبع تحويل الأحرف إلى صغيرة قواعد Unicode البسيطة: فالحرف التركي İ والحالات الخاصة المشابهة لا تتغير.
- **تشوهات البيانات المصدرية:** تؤثر الحسابات المشتركة والروبوتات والاقتباسات والرسائل المحوَّلة والنص الملصوق في النتيجة؛ ولا تُحسب رسائل تيليجرام المحوَّلة، لكن الاقتباسات داخل الرسائل العادية تبقى.
- **لم يُقيَّم التقليد المتعمد لأسلوب الآخرين ولا إعادة صياغة النص** (مخطط لإصدار لاحق).
- **الطوابع الزمنية** لازمة للإيقاع (`--rhythm`) فقط: ولا توجد في الملفات النصية.
- تُقرأ الملفات النصية بترميز UTF-8 فقط؛ ويُرفض الملف بترميز آخر برسالة واضحة بدل قراءته مشوَّهاً.
- الطريقة مغلقة: فهي تقارن بالمرشَّحين الذين سمّيتهم. وقد لا يكون الكاتب الحقيقي بينهم.

## الأخلاقيات والخصوصية

- **كل شيء يُحسب محلياً.** الوصول الوحيد إلى الشبكة هو تيليجرام (Telethon)، وبأمر صريح فقط: `chatstyle login` و`compare`/`features` مع مصدر `tg:`. لا توجد بيانات قياس عن بُعد.
- **ما الملفات التي ينشئها البرنامج.** في مجلد البيانات (`%APPDATA%\chatstyle` في Windows، و`~/.local/share/chatstyle` أو `$XDG_DATA_HOME/chatstyle` في Linux؛ ويمكن تغييره بالمتغير `CHATSTYLE_HOME`):
  - `vault.json` هي الخزنة **المشفَّرة**: مفاتيح واجهة تيليجرام والجلسة (وهي تعادل الوصول إلى حسابك)، انظر [الأمان](#الأمان)؛
  - `cache/` ذاكرة مؤقتة لرسائل محمَّلة لـ**أشخاص حقيقيين** (غير مشفَّرة)؛
  - `chats/` المحادثات المرفوعة (علامة التبويب «Чаты» و`chatstyle chats add`): نصوص رسائل **أشخاص حقيقيين** وأوقاتها، **مشفَّرة** بمفتاح الخزنة (`*.chat`)؛
  - `gui-settings.json` لغة النافذة وسمتها؛
  - `.env` مفتاحا `api_id` و`api_hash`، فقط إن وضعتهما هناك بنفسك.

  لحذف كل شيء احذف هذا المجلد (وأنهِ الجلسة في إعدادات تيليجرام: «الأجهزة»).
- **تحتوي التقارير على مقتطفات من المحادثات** (n-gram) وأسماء المصادر. لا تنشرها ولا تمرّرها دون موافقة كاتبي الرسائل. ولا تدخل التقرير أسماء ملفات مجلد `--impostors`.
- **محادثات الآخرين بيانات شخصية.** قبل تحليل محادثة احصل على موافقة المشاركين فيها وتأكد من أن قوانين بلدك تسمح بذلك. ولا يقدّم المشروع استشارات قانونية.
- **يجب ألا يحتوي المستودع على** `.env` وملفات `.session` والذاكرة المؤقتة وأي محادثات حقيقية؛ فهي مستثناة في `.gitignore`. لا تضفها إلى الإيداعات ولا إلى الأمثلة.
- **ما الذي لم تُصمَّم له الأداة:** كشف هوية أشخاص رغماً عنهم، والمراقبة، والضغط والتنمر، ودعم الاتهامات دون أدلة أخرى، وتقديم النتيجة على أنها دليل على نسبة النص إلى كاتبه.

## الأمان

**ما الذي تحمي منه.** مستخدمون آخرون لهذا الحاسوب، وسرقة القرص ومجلد البيانات أو نسخهما، والمزامنة السحابية، والنشر العرضي للملفات، والعبث بصفحة النافذة، واعتراض حركة المرور إلى تيليجرام. **ما الذي لا تحمي منه.** برنامج خبيث يعمل بحسابك، وبرنامج تسجيل المفاتيح أو تسجيل الشاشة: فإن وُجدا فلا يحفظ أي برنامج الأسرار. وللتصدي لمثل هذا التهديد اختر وضع «طوال فتح النافذة فقط» وفعّل التحقق بخطوتين في تيليجرام.

- **ثلاث طرق لحفظ تسجيل الدخول** (`chatstyle login` أو المعالج في النافذة):
  - *كلمة مرور رئيسية* (موصى بها): تُشفَّر المفاتيح والجلسة بـ AES-256-GCM، ويُشتق المفتاح من كلمة المرور بخوارزمية scrypt (64 ميغابايت، نحو 0.3 ثانية للمحاولة)، ولا تُحفظ كلمة المرور في أي مكان، وتتباطأ المحاولات بعد ثلاث إدخالات خاطئة؛ وتُقفل الخزنة تلقائياً بعد 15 دقيقة من الخمول؛
  - *حساب Windows* (DPAPI): لا حاجة إلى كلمة مرور، لكن بإمكان أي برنامج يعمل بحسابك فك تشفير تسجيل الدخول؛
  - *طوال فتح النافذة فقط*: لا يُكتب شيء على القرص، وعند إغلاق النافذة تُنهى الجلسة من جهة تيليجرام.
- **لا نكتب التشفير بأنفسنا:** AES-GCM من مكتبة `cryptography`، وscrypt من `hashlib` القياسية، وDPAPI استدعاء نظام في Windows. وملف الخزنة موثَّق: يُكتشف تلف الترويسة أو العبث بها. وكلمة المرور الرئيسية المنسية لا يمكن استعادتها: تسجّل الدخول من جديد.
- **المحادثات المرفوعة مشفَّرة** بالخزنة نفسها: مفتاح AES-256-GCM (256 بتاً، عشوائي) موجود في `vault.json` لا بجانب الملفات؛ وبدون فتح الخزنة لا يمكن قراءة المحادثات. وحذف محادثة يكتب فوق الملف أصفاراً (وفي SSD لا يضمن ذلك المحو الفعلي). فإذا عمل برنامج خبيث بحسابك والخزنة مفتوحة، فسيحصل على المحادثات أيضاً، كما يحصل على جلسة تيليجرام. ويحتفظ وضع «طوال فتح النافذة فقط» بالمحادثات في الذاكرة فقط.
- **الأذونات:** يُغلق مجلد البيانات أمام الجميع إلا حسابك (في Windows عبر `icacls`، وفي Linux بالأذونات `0700`/`0600`).
- **النافذة:** تُحمَّل الصفحة من ملف داخل الحزمة لا من خادم محلي: ليس للعملية منافذ مستمعة (والفحص الذاتي يتحقق من ذلك). وتمنع سياسة CSP أي طلب شبكة من الصفحة، ويُحظر الانتقال إلى عناوين أخرى، ولا يُستخدم تخزين المتصفح ولا الملء التلقائي (الوضع الخاص في WebView2)، وأدوات المطوّر معطَّلة. وتُختار الملفات في حوارات النافذة فقط، ولا تُفتح إلا التقارير التي أنشأتها هي، ويُفحص كل ما يصل من الصفحة نوعاً وطولاً.
- **البناء:** التبعيات مثبَّتة بالإصدار والبصمة (`packaging/requirements.lock`، وتُثبَّت بـ `pip install --require-hashes`)، ولم يجد `pip-audit` ثغرات معروفة وقت الكتابة، ويُنشأ `dist/SHA256SUMS.txt` بجانب exe. **ملف exe غير موقَّع** (يلزم شهادة)، لذا قد ينبّه SmartScreen عند أول تشغيل.
- **ملفات الإصدار السابق غير المشفَّرة** (`telegram.session` و`telegram.account`): تعرض النافذة حذفها عند العثور عليها، لأنها غير مشفَّرة. والذاكرة المؤقتة لرسائل تيليجرام (`cache/`) غير مشفَّرة بعد أيضاً.

## بنية المشروع

- **النواة (`core/`، C++17):** حسابات على النص بوصفه متتالية من نقاط رمز Unicode (من UTF-8 إلى `std::u32string`)، وn-gram وTF-IDF وجيب التمام وBurrows Delta وGeneral Impostors والتفسيرات. لا تعرف النواة شيئاً عن الملفات ولا تيليجرام ولا التقارير. والصلة بـ Python عبر pybind11 (`chatstyle._core`).
- **Python (`python/chatstyle/`):** المُجمِّعات (txt وتصدير تيليجرام وTelethon)، والمعالجة المسبقة، وخط المعالجة، وسطر الأوامر (typer وrich)، والتقارير. ولا تحسب Python السمات بنفسها.
- **أخرى:** `tests/` (pytest)، و`core/tests/` (Catch2)، و`experiments/` (تقييم الجودة، وليست جزءاً من الحزمة)، و`packaging/` (PyInstaller)، و`docs/` (التقرير التجريبي والمحادثات الخيالية)، و`.github/workflows/`.

## الحالة والثغرات المعروفة

هذا القسم مؤقت ويجب أن يختفي قبل v1.0. قائمة صادقة بما **لم يُتحقق منه**:

- **CI** (GitHub Actions) أخضر على Windows (MSVC، Python 3.12) وUbuntu (Python 3.11 و3.12): فحص الشيفرة واختبارات Python واختبارات النواة وبناء wheel وتشغيله. وفحص المشروع محلياً أيضاً على Windows 10 مع MinGW-w64 (Python 3.14). النافذة غير مشمولة في CI على Linux (لا شاشة، ويُتخطى اختبار النافذة هناك)؛ وجرى أيضاً فحص التثبيت على Linux (بناء النواة وتشغيل `chatstyle`) يدوياً على Kali Linux.
- **مُجمِّع تيليجرام فُحص على بدائل محاكاة فقط**، دون حساب حقيقي.
- **ملفات exe لنظام Windows.** يبني سير عمل الإصدار `chatstyle.exe` و`chatstyle-gui.exe` بمترجم MSVC على مشغِّل GitHub ويجري هناك اختبارات سريعة (`--version` و`compare` والفحص الذاتي للنافذة). وشُغّلت بُنى الإصدار يدوياً أيضاً على جهاز Windows 10 للمؤلف وهي تعمل. واجتازت بنية محلية بمترجم MinGW-w64 كذلك `packaging/check_exe.py` (الإصدار والأيقونة في خصائص الملف، و`PATH` بلا Python، وقراءة `.env` من `%APPDATA%\chatstyle`، والإخراج في طرفية حقيقية بعرض 80 عموداً، والانتظار عند التشغيل بالنقر المزدوج)؛ وعلى المشغِّل يعمل هذا السكربت بلا طرفية حقيقية، لذا نتيجته للاطلاع فقط. **لم يُتحقق من:** Windows 10 نظيف دون Python إطلاقاً (يكفي Windows Sandbox: انسخ إليه ملف `chatstyle.exe` واحداً وشغّل `chatstyle --version` و`compare`).
- **الحالة التي بدأ بها المشروع (حالة واحدة، وليست دليلاً).** فقد أحد المعارف الوصول إلى حسابه الرئيسي في تيليجرام وواصل الكتابة من حساب ثانٍ «توأم». أجرى المؤلف هذا الاختبار على محادثات تيليجرام روسية حقيقية، فقارن رسائل الحساب التوأم بخمسة مرشَّحين: الحساب الأصلي والمؤلف نفسه وثلاثة معارف آخرين. وضعت النسخة الأولى الخام من الأداة (جيب التمام وBurrows Delta وGeneral Impostors فقط) الكاتب الحقيقي في المرتبة **الثالثة**. وبعد إضافة الطرق الأخرى (أقسام الكلام ونموذج الأحرف اللغوي وn-gram الكلمات والرموز التعبيرية وإيقاع الكتابة ومجموعة طرق الأسلوب) صار الكاتب الحقيقي في المرتبة **الأولى**. هذه حالة واحدة، وقد طُوّرت الطرق بالنظر إلى هذه البيانات نفسها وإلى بيانات مشابهة، فهي تبيّن لماذا أُضيفت الطرق الإضافية، لا أن الأداة ستفعل الشيء نفسه معك.
- **التقييم على بيانات حقيقية بيئة محادثة واحدة، واختيار الطريقة جرى ضبطه عليها.** أُجري الفحص على محادثات مستخدم واحد: مجموعتان (202 و16 مشاركاً) ومحادثات خاصة. المهام: شخص من سياق واحد (محادثة) مقابل أشخاص آخرين تؤخذ نصوصهم من محادثات أخرى (25 مهمة)، وقسمة بالزمن داخل مجموعة (16)، وحالة حقيقية واحدة لـ«حساب توأم» (2)؛ لدى جميع المرشَّحين 2500 كلمة لكل منهم، وللنص المجهول 600-1400 كلمة، والمرشَّحون من 10 إلى 36. المرتبة الأولى للكاتب الحقيقي: المجموعة الكاملة مع المفردات (النموذج اللغوي والكلمات و«الهيكل» وDelta) 95% (MRR 0.97)، ومجموعة الأسلوب (الافتراضية: «الهيكل» وDelta ونموذج لغوي بلا كلمات نادرة) 91% (MRR 0.93)؛ وفي مهام «عبر السياقات» هي 92% مقابل 84%: تدفع مجموعة الأسلوب بضع نقاط ثمناً للاستقلال عن الموضوع (وفي 129 تشغيلاً «الكاتب الحقيقي و3 منافسين» تنال الكاملة 98% ومجموعة الأسلوب 95%)؛ وكلٌّ على حدة: النموذج اللغوي 88%، وn-gram الكلمات 88%، وDelta 72%، و«الهيكل» 72%، وImpostors مع المرشَّحين الآخرين بدور الغرباء 58%، وجيب تمام TF-IDF 56%. وإذا أُبقي الكاتب الحقيقي و3 منافسين عشوائيين (129 تشغيلاً، والتخمين العشوائي 25%): المجموعة الكاملة 98%، وDelta 88%، وجيب التمام 84%، وImpostors 75%. ولم تكن الأوزان المضبوطة للمجموعة أفضل من المتساوية (اختبار «ترك شخص خارجاً»، والفرق ضمن الضوضاء)، ولم تغيّر إضافة «خلفية» من عشرات الكُتّاب الغرباء لدرجات z شيئاً، لذا فالأوزان متساوية ولا خلفية.
  **كيف تتعامل مع هذا:** هذه بيئة واحدة (محادثات روسية لدائرة واحدة، فيها كثير من الكلمات والموضوعات المشتركة)، والمهام تعتمد بعضها على بعض، واختيرت الطرق الأربع من نحو عشر على البيانات نفسها، لذا فالأرقام متفائلة وقد لا تنطبق على أشخاص ولغات وأحجام أخرى. والنموذج اللغوي وn-gram الكلمات حساسان للمفردات والموضوع (ويعوّض عن ذلك جزئياً أن المجهول والمرشَّحين مأخوذون من محادثات مختلفة)؛ أما «الهيكل» وDelta فيتوقفان على الموضوع قليلاً.
  **كم نصاً يلزم** (مهام «عبر السياقات» والحقيقية، 27 مهمة، وضوضاء نحو ±7 نقاط). نص الكاتب المجهول، المرتبة الأولى لمجموعة الأسلوب / المجموعة مع المفردات: 300 كلمة 67% / 70%، و600 70% / 93%، و1000 85% / 96%، و2000 81% / 96%، و4000 89% / 93%. فمجموعة الأسلوب لا تكاد تزداد مع زيادة النص (وتقف في هذه البيانات عند 85-90%)، بينما تعطي المفردات 93% وأكثر عند 600 كلمة: فإن كان لدى الكاتب المجهول أقل من 1000 كلمة فاستخدم `--lexical` (ويذكّرك البرنامج بذلك بنفسه بتلميح في الجدول والتقارير والنافذة). حجم المرشَّحين (متساوٍ للجميع): 2500 كلمة لكل منهم 93% / 98%، و5000 86% / 93%، و10000 88% / 95%؛ وكلما ساءت تسوية الأحجام ساءت النتيجة، لذا فالحد الافتراضي 2500 كلمة (لكن ليس أقل مما لدى الأقصر). وتعطي عينات عشوائية مختلفة من الرسائل بالحجم نفسه تبايناً إضافياً بمقدار 2-3 نقاط. وقد أيّد اختبار أول على 5 مرشَّحين «Delta بجيب التمام»؛ وعلى 36 مرشَّحاً لم يتأكد ذلك: فقد تبيّن أن الاستنتاج من عينة صغيرة خاطئ، ولم تعد هذه الطريقة في البرنامج.
